## Lesson 4.1: Generator の双方向通信 (`send()`, `throw()`) と遅延評価

- **検証日**: 2026-10-02
- **検証コード**:
  - 実証スクリプト: `src/Phase4/Lesson4_1_GeneratorBidirectional.php`
  - Pestテスト: `tests/Unit/Phase4/Lesson4_1_GeneratorBidirectionalTest.php`

### 1. 検証した言語仕様・テーマ
- ジェネレータの遅延評価（Lazy Execution）とライフサイクル（関数呼び出し時点では 1 行も走らず、`current()` / `rewind()` で初めてスタートする仕様）。
- `yield` 式の評価順序（右辺の送信と一時停止、再開後の評価値代入）。
- `send($value)` による一時停止中ジェネレータへの双方向値注入（コルーチン）と、次の `yield` への進行。
- `throw($exception)` による外部からの例外割り込み注入と、ジェネレータ内部の `try-catch` による生存リカバリ。
- PHP 7.0 の `getReturn()`（ジェネレータの最終戻り値）と `yield from`（委譲ジェネレータ / Generator Delegation）。

### 2. 実施したテスト・検証概要
- 遅延実行のライフサイクル検証:
  - `$gen = myGen($logs)` 実行直後は `$logs` が空配列（`toBe([])`）であり、関数内のコードが一切実行されていないこと。
  - 1 回目の `current()` で初めて暗黙の `rewind()` が走り、最初の `yield` までのログ（`['one']`）が記録され `1` が返ること。
  - 以降、`current()` を何回連続で呼んでも実行位置は進まないこと（`next()` または `send()` のみで進む）。
- `send()` の双方向通信と戻り値:
  - `$gen->current()` で `1` を取得。
  - `$gen->send('Hello')` を呼ぶと、内部の `$received` に `'Hello'` が注入され、そのまま次の `yield` まで進んで戻り値として `2` が返ること。
- `throw()` による外部例外注入とリカバリ:
  - 外部から `$gen->throw(new RuntimeException('Error'))` を実行。
  - 内部の `catch` ブロックが例外を安全に処理し、ジェネレータが破棄されずに `'received'` を yield して生き残ること。
  - その後の `next()` で後続の `yield 2` に正常到達すること。

### 3. 直面した落とし穴・内部挙動の気付き
- **ジェネレータ関数は呼び出された瞬間は「未スタート」**:
  - 普通の関数と違い、呼び出し時はただ `Generator` オブジェクトをメモリに割り当てるだけで関数本体のオペコードは実行されない。最初の `current()` や `rewind()`、`valid()` で初めて実行が始まる。
- **`$received = (yield 1)` の 2 段階評価**:
  - `yield 1` で `1` が外に出た瞬間、関数の実行がストップする（まだ代入は行われない）。外から `send('Hello')` されて再開したときに初めて `(yield 1)` 全体が `'Hello'` と評価され、左辺に代入される。
- **`current()` は現在値を覗くだけ、動かすのは `next()` / `send()`**:
  - 1 回目の `current()` だけは暗黙の `rewind()` により最初の yield まで動くが、2 回目以降は何度呼んでもカーソルは進まない。
- **`throw()` によるリカバリ**:
  - 内部で例外をキャッチすれば、ジェネレータは死なずにループや後続処理を続行できる。非同期フレームワークでタスクのエラーリトライ等に利用される重要パターン。

### 4. 実務・Qiita 向けのアウトプット要点
- 大量データ（数万〜数百メガバイトの CSV やログファイル）を処理する際、全データを配列にロードするとメモリ枯渇（Fatal Error: Allowed memory size exhausted）するが、ジェネレータを使えばメモリ使用量を数キロバイトに抑えたストリーム処理が可能。
- ジェネレータは単なる「メモリ節約イテレータ」にとどまらず、`send()` と `throw()` を備えた「双方向コルーチン（Coroutine）」であり、PHP 8.1 の Fiber が登場する前の並行・非同期処理（Amp / ReactPHP）のコア基盤として利用されていた。

## Lesson 1.1: 緩やかな比較 (==) の PHP 8 における刷新と型ジャグリング境界

- **検証日**: 2026-09-27
- **検証コード**:
  - 実証スクリプト: `src/Phase1/Lesson1_1_LooseComparison.php`
  - Pestテスト: `tests/Unit/Phase1/Lesson1_1_LooseComparisonTest.php`

### 1. 検証した言語仕様・テーマ
- PHP 8.0 の "Saner string to number comparisons" RFC による緩やかな比較 (`==`) の仕様刷新。
- 数値と数値形式文字列 (numeric string) の比較判定規則。
- 文字列同士の比較における暗黙の数値評価（`"42" == "42.0"`）。
- `in_array()` における型ジャグリング起因の判定の罠。

### 2. 実施したテスト・検証概要
- `0 == '0'`, `0 == '0.0'`, `42 == '  42  '`, `'42' == '42.0'` が `true` となる挙動。
- `0 == 'foo'`, `0 == ''` が PHP 8 では `false` となる挙動（PHP 7 では `true` だった）。
- `in_array(0, ['pending', 'approved', 'rejected'])` が、PHP 8 では `false` となる挙動（PHP 7 では先頭の `'pending'` にマッチして `true` に誤認されていた）。

### 3. 直面した落とし穴・内部挙動の気付き
- **型変換の方向性の逆転**:
  - PHP 7: 「文字列側を数値にキャスト」していたため、非数値文字列 `"foo"` が `0` に変換されて `0 == "foo"` が `true` になっていた。
  - PHP 8: 「非数値文字列との比較時は、数値側を文字列にキャスト（`"0" == "foo"`）」するよう仕様が改修され、直感的な `false` になった。
- **Zend Engine の数値文字列判定**:
  - 文字列同士であっても、`==` は `is_numeric_string()` で両辺をスキャンし、数値形式であれば double/long にキャストして比較する。そのためマジックハッシュ（`0e...`）の脆弱性に繋がるリスクを理解した。
- **PHPStan (Level: max) の指摘**:
  - リテラル同士の `0 == 'foo'` などに対して「常に false/true になる」と警告を出し、実行前の段階でデッドコード・比較の不整合を検出できることを実感。

### 4. 実務・Qiita 向けのアウトプット要点
- `in_array()` を使う際は、必ず第3引数に `$strict = true` を指定する。
- 業務ロジックのステータス管理や識別子には文字列や数値の素の比較を避け、PHP 8.1+ の **Backed Enum** を採用して型安全性を担保する。
- パスワードハッシュやトークンの検証には `==` を使わず、`hash_equals()` または `===` を徹底する。

## Lesson 1.2: 宇宙船演算子 (<=>) と複合ソートアルゴリズム

- **検証日**: 2026-09-27
- **検証コード**:
  - 実証スクリプト: `src/Phase1/Lesson1_2_SpaceshipOperator.php`
  - Pestテスト: `tests/Unit/Phase1/Lesson1_2_SpaceshipOperatorTest.php`

### 1. 検証した言語仕様・テーマ
- 宇宙船演算子 (`<=>` / Combined Comparison Operator) の戻り値契約 (`-1`, `0`, `1`)。
- 配列同士の `<=>` 比較仕様（要素数・先頭要素優先・連想配列の一致判定）。
- `NAN` に対する `<=>` の全順序維持のための特殊挙動（`NAN <=> 0` が `1`）。
- `usort()` における複数条件ソート（短絡エルビス演算子 `?:` チェーン vs タプル配列比較）。
- PHP 8.0 におけるソート関数の全面「安定ソート (Stable Sort)」化。

### 2. 実施したテスト・検証概要
- 基本比較:
  - `"10" <=> 2` が `1`（数値形式文字列の数値変換）。
  - `[1, 2] <=> [1, 2, 3]` が `-1`（要素数の少なさが優先）。
  - `[1, 9] <=> [2, 0]` が `-1`（先頭要素で決定）。
  - `['a' => 1, 'b' => 2] <=> ['b' => 2, 'a' => 1]` が `0`（順序が異なってもキーと値の一致で等しい）。
  - `NAN <=> 0` が `1`（ソート崩壊防止のため NAN は全数値より大）。
- 複合ソート:
  - スコア降順 → 年齢昇順 → 名前昇順の3重ソートをタプル配列比較 `[$b['score'], $a['age'], $a['name']] <=> [$a['score'], $b['age'], $b['name']]` にて 1 行で実装・検証。

### 3. 直面した落とし穴・内部挙動の気付き
- **配列のタプル比較の簡潔さ**:
  - `usort()` のコールバック内で `[$b['score'], $a['age']] <=> [$a['score'], $b['age']]` と書くだけで、先頭要素から順に比較され差がついた時点で勝敗が決まるため、条件分岐のネストが不要になる。
- **エルビス演算子 `?:` との適合性**:
  - `<=>` が同点時に返す `0` は PHP では falsy（偽値）であるため、`($b['score'] <=> $a['score']) ?: ($a['age'] <=> $b['age'])` で同点時のみ次へ流す短絡評価が成立する。
- **PHP 8 の安定ソート**:
  - PHP 7 以前は不安定ソート（同点の順序が不定）だったが、PHP 8.0 で全ソートが安定ソートになったため、予期せぬ順序の入れ替わりが解消された。

### 4. 実務・Qiita 向けのアウトプット要点
- 複数キーのソートは、`usort()` + アロー関数 + タプル比較（またはエルビス短絡）で書くと可読性と保守性が最大化される。
- PHP 8 から安定ソートが言語仕様として保証されているため、同点時に元の順序を維持したい場合のワークアラウンドが不要になった。

## Lesson 1.3: ビット演算・論理演算子の短絡評価と優先順位の罠

- **検証日**: 2026-09-27
- **検証コード**:
  - 実証スクリプト: `src/Phase1/Lesson1_3_BitwiseAndPrecedence.php`
  - Pestテスト: `tests/Unit/Phase1/Lesson1_3_BitwiseAndPrecedenceTest.php`

### 1. 検証した言語仕様・テーマ
- 代入演算子 (`=`) と論理演算子 (`&&` vs `and`) の優先順位の決定的な違い。
- 文字列連結 (`.`) と算術加算 (`+`) の優先順位（PHP 7 の左結合同一優先度から、PHP 8 の加算優先への歴史的変更）。
- ビット演算子 (`&`) と厳密比較 (`===`) の優先順位の罠（括弧を忘れると bool ではなく int になる）。
- 論理演算子の短絡評価（Short-circuit evaluation）と右辺関数の副作用スキップ。
- ビットマスク（ビット論理積 `&`）による型安全な権限判定の実装。

### 2. 実施したテスト・検証概要
- `&&` vs `and`:
  - `$x = true && false` が `false` になることの検証（`&&` が高優先度）。
  - `$y = true and false` が `true` になることの検証（`=` が `and` より優先され先に代入される）。
- 文字列連結と加算:
  - `"Sum: " . 3 + 5` が PHP 8 では `"Sum: 8"` になることの検証（PHP 7 では `0 + 5 = 5` になっていた）。
- ビット演算と厳密比較:
  - `$flags & $mask === $mask` が、結合順序 `$flags & ($mask === $mask)` により `int(1)` になってしまう挙動の検証。
- 短絡評価:
  - `true || $trigger()` において、左辺が真のため右辺のクロージャが実行されず、副作用フラグが `false` のまま維持されることの検証。
- 実務ビットフラグ判定:
  - `READ | EXECUTE` を保持するユーザーに対し、`($user & $permission) === $permission` の括弧付き判定式で `READ` / `EXECUTE` が true、`WRITE` が false となることの検証。

### 3. 直面した落とし穴・内部挙動の気付き
- **PHP 7 における `"Sum: " . 3 + 5` の怪奇挙動**:
  - 同一優先度・左結合のため、`("Sum: " . 3) + 5` → `"Sum: 3" + 5` となり、文字列の先頭非数値キャストで `0` に化けて最終結果が数値の `5` になるという強烈な落とし穴を理解した。
- **ビット判定での括弧忘れの恐怖**:
  - `===` は `&` より優先順位が高いため、`$flags & $mask === $mask` は右側が先に評価されて `true` (1) になり、最終的な型が `int` になってしまう。`=== true` で判定すると権限があるのに失敗する。必ず `($flags & $mask) === $mask` と括弧で囲む必要がある。
- **`and` / `or` の実務での使い所**:
  - 通常の条件分岐には `&&` / `||` を使うのが絶対のベストプラクティス。`or` は Perl 由来の `doSomething() or die();` のような制御フロー以外で使ってはならない。

### 4. 実務・Qiita 向けのアウトプット要点
- 演算子優先順位に依存したコードは可読性と安全性を著しく損なう。ビット判定や複合論理式では **「迷ったら括弧 `()` を書く」** をチーム規約レベルで徹底する。
- 権限管理にビットフラグを採用する場合、判定ロジックはヘルパー関数/メソッドにカプセル化し、呼び出し側にビット演算を書かせない設計にする。
